<objective>
Extract kv.ee scraping (Playwright + CF cookie harvest + individual listing fetch + HTML parsing) into a standalone Docker container that runs on Daniel's home mini PC. The container has no VPS dependencies (no FastAPI, no APScheduler, no data_store), and its entry point runs a while-True loop that scrapes, serializes Listing objects via dataclasses.asdict(), POSTs the batch to `{VPS_INGEST_URL}/api/ingest`, and POSTs a heartbeat to `{VPS_INGEST_URL}/api/heartbeat`. This is the user-facing side of the vertical slice — running this container is what makes the whole architecture split work end-to-end (per D-01, D-03, D-04, D-05).

Purpose: Move Cloudflare-facing scraping off the VPS datacenter IP (which is blocked) and onto Daniel's residential IP. Satisfies ARCH-01 (standalone scraper client runs on home mini PC, Windows/macOS compatible).

Output: A new `scraper-client/` subfolder with a buildable Docker image, `.env.example`, and Python source files. Together with plan 01-02 (which lands the receiving `/api/ingest` and `/api/heartbeat` endpoints) this delivers the first end-to-end slice: mini PC scrapes → VPS receives → VPS evaluates. Plan 01-02 owns disjoint files (only `app/**` and `Caddyfile`), so both plans run in parallel in Wave 1.
</objective>
