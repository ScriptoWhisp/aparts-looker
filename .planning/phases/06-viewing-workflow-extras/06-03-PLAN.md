<objective>
VIEW-03 vertical slice. After this plan, when Daniel schedules a viewing, the backend auto-generates a Russian negotiation brief (single paragraph, 4-8 sentences) grounded in concrete numbers from the listing's data, with a suggested opening-offer range in EUR. The brief appears as a new card on the detail panel below the AI Verdict block. A "Regenerate brief" button allows on-demand refresh (e.g. after a price drop).

Purpose: give Daniel a talking-point-grounded document to bring to the viewing / initial-offer negotiation, per the D-05 spec ("well-written 4-8 sentence paragraph that weaves in the listing's age, price trajectory, how the €/m² compares to the district running average, any renovation/parking signals, and a suggested opening offer range with reasoning").

Output:
- New Python module `app/brief_generator.py` (~200 lines, mirroring `ai_evaluator.py`).
- New POST endpoint `/api/entry/{id}/regenerate-brief` on `main.py`.
- Update `/api/entry/{id}/schedule-viewing` endpoint (from Plan 06-02) to spawn a daemon thread calling `brief_generator.generate_and_save_brief`.
- New detail-panel card + Regenerate button.
- 3 GREEN unit tests + 1 GREEN integration test.

Artifacts this phase produces:
- `brief_generator.generate_negotiation_brief(entry: dict, price_history: list, district_avg_price_per_sqm: Optional[int], coo_monthly_eur: Optional[int]) -> dict` — pure function, mocks-friendly.
- `brief_generator.generate_and_save_brief(listing_id: str) -> None` — daemon-thread target; snapshots-under-lock, HTTP-outside-lock, save-under-lock (Pitfall 5).
- `brief_generator._extract_json(text: str) -> dict` — reuses ai_evaluator's regex-strip pattern.
- `brief_generator._validate_no_hallucinated_numbers(brief: str, authoritative: dict) -> bool` — post-hoc grounding check.
- `brief_generator.SYSTEM_PROMPT` — Russian system prompt with strict JSON output requirement.
- FastAPI endpoint `POST /api/entry/{listing_id}/regenerate-brief` (no body).
- JS function `regenerateBriefClick(listingId)`.
- JS function `_buildNegotiationBrief(brief, entry)` — vanilla-JS card DOM.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API->Anthropic | Outbound HTTPS to api.anthropic.com; API key in x-api-key header |
| Anthropic->persistence | AI output stored on entry.negotiation_brief; rendered via textContent to prevent XSS |
| listing description->Anthropic prompt | Potential prompt-injection surface via listing text |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-06 | Tampering | Prompt injection via listing description | medium | mitigate | AUTHORITATIVE FACTS block delimits data from model instructions; SYSTEM_PROMPT commands strict JSON output; output rendered via textContent only. |
| T-06-07 | Information Disclosure | API key logged | high | mitigate | Never log ANTHROPIC_API_KEY; log listing_id only per 06-RESEARCH.md § Security Domain. |
| T-06-08 | Integrity | Hallucinated numbers in brief | medium | mitigate | `_validate_no_hallucinated_numbers` post-hoc check flags mismatches with `needs_review=True`; UI shows warning badge. |
| T-06-09 | Availability | Runaway brief regeneration | low | mitigate | Client-side debounce on Regenerate button (2s); server threads are cheap and Anthropic bills per call. |
</threat_model>
