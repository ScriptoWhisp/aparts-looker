<objective>
ENRICH-01 vertical slice. After this plan, every listing that transitions from pending → approved (either via `/api/pending/{id}/approve` or via Telegram callback) automatically fires a best-effort KÜ (korteriühistu) lookup against Estonia's e-Business Register autocomplete endpoint. When found, a compact KÜ card appears in the detail panel showing the KÜ name, reg_code, canonical ariregister URL, and a manual-notes text area for Daniel to paste facts from meeting minutes. When no KÜ is found, the card is hidden entirely (D-13 hide-when-empty). Daniel can force a re-fetch via a "Refresh KÜ" button on the detail panel.

Purpose: surface building-fund realities (or at least the fact that a registered KÜ exists at this address, with a link) so Daniel doesn't sign an offer on a building with an unknown or missing owners' association. Per D-11: "Best-effort scrape... never-raise... a failed lookup is a no-op, not an error."

Output:
- New Python module `app/ku_lookup.py`.
- Approval-hook dispatcher (in `ingest_handler.py` or `main.py`) that spawns a KÜ-lookup thread on approval.
- New POST endpoint `/api/entry/{id}/refresh-ku`.
- New detail-panel card + Refresh button + manual notes textarea.
- 3 GREEN unit tests + 1 GREEN integration test.

Artifacts this phase produces:
- `ku_lookup.lookup_ku_for_address(address: str) -> Optional[dict]` — pure function, never-raises.
- `ku_lookup._to_street_query(address: str) -> str` — normaliser (drops apartment suffix + city).
- `ku_lookup.AUTOCOMPLETE_URL = "https://ariregister.rik.ee/est/api/autocomplete"`.
- `ku_lookup.KORTERIUHISTU_LEGAL_FORM = "23"`.
- FastAPI endpoint `POST /api/entry/{listing_id}/refresh-ku` (no body).
- Approval hook: `ingest_handler._dispatch_ku_lookup(listing_id: str) -> None` OR inline `threading.Thread(...)` inside the approve-pending handler.
- JS function `refreshKuClick(listingId)`.
- JS function `_buildKuCard(ku, entry)` — vanilla-JS card DOM with manual notes textarea.
- JS function `saveKuManualNotes(listingId, notes)` (uses existing PUT /api/data path per RESEARCH.md A1 — no new backend endpoint for manual notes; the existing PUT /api/data flow is the persistence path).
</objective>
