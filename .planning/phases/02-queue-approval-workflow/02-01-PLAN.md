## Phase Goal

**As** Daniel (single-user apartment hunter), **I want to** have every newly-evaluated listing land in a pending review queue rather than the main dossier, **so that** I can approve or reject each one myself before it clutters my curated list of candidates.

*(Story synthesised from ROADMAP goal + CONTEXT decisions. Underlying phase intent: no listing reaches the dossier without my explicit approval.)*

<objective>
Foundational vertical slice for Phase 2: extend the data model with a `pending[]` + `rejected[]` queue, wire `ingest_handler.process_ingest_batch()` to write into `pending[]` instead of `properties[]`, and lay Wave 0 test scaffolding so subsequent slices (02-02, 02-03, 02-04) have automated feedback from task 1.

Purpose: Every downstream slice depends on the pending queue existing. Once this plan ships, ingested listings stop polluting the dossier immediately — even without any UI or Telegram wiring, the safety property "no listing reaches properties[] without approval" holds. QUEUE-01 is satisfied end-to-end.

Output:
- Extended `data_store.py` with pending/rejected state, atomic-move helpers, and a `_pending_to_property()` bridge
- Rewired `ingest_handler.py` that skips `add_property_if_new()` and calls `add_to_pending()` instead
- Wave 0 test scaffold (`app/tests/test_pending.py`) with stubs for QUEUE-01 through QUEUE-07 so later plans can `pytest` immediately
- New conftest fixtures (`mock_send_pending_card`, `mock_gmail`) reused by all Phase 2 tests
</objective>
